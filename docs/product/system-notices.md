# SYSTEMお知らせ運用・過去アップデート一覧

最終更新: 2026-10-03

## 目的

SYSTEMお知らせは、利用者が「何が変わったか」「何を知っておくべきか」を理解するためのものです。内部実装の履歴をそのまま並べる場所ではありません。

- 利用者の操作や使い方が変わる大きな更新を中心に載せる。
- 内部イベント名、migration名、API名、DB名、技術用語だけで説明しない。
- 似た変更が短期間に複数ある場合は、利用者から見て1つのテーマにまとめる。
- 単純な不具合修正、文言修正、内部リファクタは原則お知らせにしない。
- 過去分を追加するときは、現在日時ではなく実際の提供時期に近い`publish_at`を使い、時系列を壊さない。
- 一度productionへ適用したお知らせmigrationは書き換えない。

## 今後のお知らせ作成

利用者向けの大きな変更は[`../engineering/change-policy.md`](../engineering/change-policy.md)に従い、機能変更と同じ変更セットで新しいお知らせmigrationを作成します。

通常の新規お知らせ:

```bash
npm run release:notice -- --slug feature-name --title "新機能のお知らせ" --body "利用者向け説明"
```

過去分を追加する必要がある場合:

```bash
npm run release:notice -- --slug historical-feature --title "過去のお知らせ" --body "利用者向け説明" --publish-at "2026-09-26T00:00:00Z"
```

過去分は、既存のお知らせと内容が重複しないかこのファイルとSYSTEM管理画面を確認してから追加します。

## 文章ルール

タイトルは「〜できるようになりました」「〜を見直しました」のように、利用者が変更点を一読で理解できる表現にします。本文は1〜3文を目安にし、利用者が実際にできること・変わることを先に書きます。

避ける例:

```text
admin.display_name.updateを追加しました
0024 migrationを適用しました
EntitlementServiceを変更しました
```

推奨例:

```text
チームごとに管理者名を設定できるようになりました
同じ管理者アカウントでも、子どものチームごとに表示名を分けて設定できます。
```
